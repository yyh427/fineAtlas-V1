Status: candidate work in progress. **v1.10.1 remains the recommended formal
release.** Source-eight construction, source-nine review, candidate acceptance
and public verification are separate checkpoints. This document records the
continuation contract; it does not certify a completed v1.11.0rc1 artifact.

## Preserve the actual parent

Continue from the two completed source-eight artifacts. Do not replay source
collection or the earlier repair stages. Keep each actual six-stage build receipt,
its complete integrity report, original inputs and original executable bytes.
The parent databases must have independent build IDs and distinct inodes, with
the same graph revision and frozen inventories. Their whole-file hashes may
legitimately differ; compare each file against its own integrity receipt.

The final nominal continuation uses `resume_nominal_design_scope_repairs.py`:

1. Verify the complete source-eight parent copy and protected production files.
2. Apply the independently approved, frozen nominal-scope operations.
3. Recompute all relation graphs.
4. Freeze exact source inputs, executable code and SDK packaging.
5. Rebuild browse staging.
6. Embed current browse indexes and write the complete build receipt.

An operation count or a source-only preflight is not a final build receipt.

## Distinguish source objects, roles and relationships

A source object with no original profile or normalization row keeps `null` in
its before-state history. A later canonical role does not fabricate an old
profile. Preserve original rank, source role, UID, native data and first
normalization history. Review a reusable nominal design as `MODEL`, a whole
multi-model programme as `MODEL_FAMILY`, and an evidenced operating physical
individual as `INSTANCE`. Each transition requires complete source review.

Unresolved design-versus-individual grain uses `UNKNOWN` with review confidence
and explicit view quarantine. Keep its original source declaration; do not
assert model generations, commercial identity or a usable hierarchy distance.
Verified role corrections preserve existing view restrictions.

A repaired whole-source direction uses `NATIVE_DESIGN_PARENT`,
`DESIGN_TYPE_OF`, `INSTANCE_OF`, or an ordinary class `IS_A` as appropriate to
its endpoints. Physical intension, design family, function and purpose remain
separate declared axes. A comparison with another object, a component, a later
derivative or a union of incompatible scopes does not prove inclusion of the
whole source object.

A withdrawal changes only the exact audited assertion's status. Retain its ID,
source, original reason, native statement, provenance and complete change
history. Multiple original assertions in the same direction require separate
row-level checks and history; one reviewed direction cannot authorize rewriting
all assertions between two endpoints.
